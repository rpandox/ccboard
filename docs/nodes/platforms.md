# Nodes on each platform

For people who run a board on a Mac, WSL2 or a container as a node.

[Back to the documentation index](../README.md)

#### Several devices (issue #154; phase P6)

A Mac and a Windows machine running the board inside WSL2 can be nodes next to the Linux box. Phase P6 made their card, their discovery and their Doctor rows honest; phase P16 pinned how routing treats them, where a repository is found and what sleep and wake do (the last three bullets). Everything marked "to verify" has been run on fakes only, not on a real Mac or a real Windows machine. A machine that runs no board at all is not a node; see [Devices without a board](device-check.md#devices-without-a-board).

- **The card on a Mac.** `os.system` is `Darwin`, `runtime` is `launchd`, `load` fields that cannot be read are `null` (shown as "n/a", never 0) and `accounts.supported` is false, shown as "Saved logins are not available on a Mac. Normal login still works." Routing counts the current account only.
- **The card on WSL2.** `os.system` is `Linux` and `os.wsl` is `true` (read from `/proc/version`; the key is absent on every other system, so a Linux card is unchanged). With no Tailscale client the board can use, the node id is `n_` and 16 hex characters, so set `CCBOARD_NODE_NAME` (the name) and `CCBOARD_PUBLIC_URL` (the address other boards are told); the card's `url` is that setting.
- **Discovery.** On a Mac the Tailscale client of issue #126 finds the app bundle's binary (`/Applications/Tailscale.app/Contents/MacOS/Tailscale`, run with `TAILSCALE_BE_CLI=1`), so no install of the command is needed. In WSL2 with no `tailscale` in the distro the list says "Tailscale runs on the Windows side: type the other node's address in Pair a node", runs no command, and Add node stays available. `tailscale.exe` reached through Windows interop is used only when `CCBOARD_TAILSCALE_PLACEMENT=host` is set (off by default, never assumed; to verify on a real machine, issue #130).
- **Doctor rows (group Box, read only; listed on a Mac or in WSL2 only).** `node-mac-public-url` (`CCBOARD_PUBLIC_URL` is set to an https address), `node-sleep` (something holds idle sleep off; if not, the fix names `caffeinate -s` for a long run, to verify on the target macOS), `node-wsl-keepalive` (the Windows keep-alive of the [Windows section](../install/windows-wsl2.md#windows-wsl2-issue-118) is running; unknown, not pass, when interop is off) and `node-gh` (a `gh` login exists; only the exit code of `gh auth status` is read). Each warning carries a fix text.
- **The Mac's own browser and the Mac's own board.** A same-Mac request through the tailnet https name carries the identity (measured with curl, measured 2026-10-10 on an Intel Mac, macOS 14, issue #130 M1); only plain `http://localhost` does not (enable the optional local sign-in and run `bin/ccboard-open` for localhost). The later device result on [#127](https://github.com/rpandox/ccboard/issues/127) confirms identity in a browser on the same Mac through its tailnet address. A development authentication bypass is never the fallback.
- **Routing on these platforms (phase P16).** A Mac whose card says `accounts.supported` is false counts as one account of its own: it shares a rate-limit window with no other node and is never left out for that. A node whose load is unknown (`null`) sorts after the nodes that have a load and is not left out either. Pinned by `test_mac_routing_counts_one_account_and_is_never_excluded` and `test_null_load_sorts_after_loaded_nodes_and_is_not_excluded` in `tests/test_nodes_failures.py`.
- **Repositories (phase P16).** A clone is found by the `origin` remote, wherever it lives, not by the projects folder (`PROJECTS_DIR` is not `/srv/projects` on a Mac). With no clone the work route answers `repo_not_here` in plain words and nothing is claimed. Pinned by `test_repo_not_here_wherever_the_clone_is`.
- **Sleep and wake (phase P16).** A sleeping Mac, or a WSL2 node without its keep-alive, shows stale and then offline, never broken. On wake the first reading shows it online again with no refresh; a claim it held is either still live or fenced: if another node took the issue while it slept, the returning node's next write is refused, its task is parked as lost and nothing is posted. Pinned by `test_sleep_and_wake_past_the_lease_the_other_node_reclaims_and_the_returning_node_is_fenced_and_parked`.

To verify on real machines (issues #130 and #155): the Mac and WSL2 cards and discovery on real hardware, WSL2 localhost forwarding, Tailscale on the Windows host, and `caffeinate -s` on the target macOS. `tests/test_nodes_platforms.py` keeps the platform rows of the table equal to `SUPPORT_PLATFORMS` in `app/nodes.py`.
