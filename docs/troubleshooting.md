# Troubleshooting and FAQ

For anyone whose board is not behaving.

[Back to the documentation index](README.md)

In this page, "the box" means the machine that runs the board.

Start with the table. Each row is a symptom you can see, the usual cause and what to do. Settings > Doctor checks most of these for you and prints the fix next to each failing row; the table says which row to read. The longer notes the table points to are under [Details](#details). Questions people ask before installing are in the [FAQ](#faq).

## Troubleshooting

### Symptom, cause, fix

| Symptom | Likely cause | What to do |
|---|---|---|
| The board answers 403 when you open `http://localhost:8000` (or the machine's own address) | A request that does not come through `tailscale serve` carries no Tailscale identity, and the board lets in only the logins in `CCBOARD_ALLOWED_USERS`. | Open the printed `https://<name>.<tailnet>.ts.net` address from another device on your tailnet. On that one machine, either use the same https name, or switch on local sign-in (`CCBOARD_LOCAL_SIGNIN=1 ./install.sh`) and run `bin/ccboard-open`. `curl http://127.0.0.1:8000/healthz` is the on-machine health check and answers `ok` while the board runs. See [Security](security.md#security-model). |
| The board does not open from your phone | The phone is not on the tailnet (the Tailscale app is off). Or the address is missing its port (`:8443` when you chose another `CCBOARD_HTTPS_PORT`). Or the tailnet has no MagicDNS or HTTPS certificates. Or you are signed in to Tailscale as a login that is not in `CCBOARD_ALLOWED_USERS` (that is a 403, not a timeout). Or the phone is a tagged device, whose browsers carry no identity. | Turn the Tailscale app on and open the exact Dashboard address the installer printed. On the machine, `tailscale serve status` lists the mappings, and Settings > Doctor, `tailscale` row, says whether MagicDNS and HTTPS certificates are on. The first request to a port right after `tailscale serve` started it can wait for its certificate: retry once. Never tag a device you browse from. See [Tailscale](install/tailscale.md). |
| A Mac board is unreachable after a while | The Mac went to sleep, or you logged out. | Idle sleep makes the board unreachable until the Mac wakes, and a logout stops the jobs and every session in them. `CCBOARD_KEEP_AWAKE=1 ./install.sh` also runs `dev.ccboard.awake` (`caffeinate -i`). See [What survives what](install/macos.md#daily-use). |
| The terminal page is blank, or an error comes back from `/tty` | ttyd is not listening, or the tmux server that owns the sessions is down, or the first request is still waiting for its certificate. | Settings > Doctor, `ttyd` row ("ttyd is installed but nothing listens on 127.0.0.1:7681") says `sudo systemctl restart ccboard-ttyd` (on a Mac `launchctl kickstart -k gui/$(id -u)/dev.ccboard.ttyd`). A "ccboard-tmux is not running" banner means `sudo systemctl start ccboard-tmux`; never restart it while sessions run. |
| A "ccboard-tmux is not running" banner, or Doctor says "no tmux server on socket 'ccboard'" | The unit that owns the tmux server is stopped. | `sudo systemctl start ccboard-tmux` (Mac: `launchctl kickstart gui/$(id -u)/dev.ccboard.tmux`). Starting it is safe; restarting it ends every session. |
| Permission prompts do not show in Needs you | The Claude hooks are not installed (Doctor: "the board's hooks are not installed in Claude's settings.json"). Or `curl` or `python3` is missing on the hooks' PATH (Doctor, Hook helpers row: the permission hook then prints nothing and the normal terminal prompt appears). Or you are attached to that terminal, where the prompt appears at once in the terminal. Or the board waited the 90 seconds (`CCBOARD_APPROVE_TIMEOUT`) and the terminal prompt took over. For Codex: its one-time hook review was not done, or `CCBOARD_REMOTE_APPROVE=0`. | Run the install line the Doctor row shows: `python3 scripts/claude_settings.py install --app-dir <ccboard folder>`. Install the missing helper the Doctor names. For Codex, run `codex` once on the machine and review the hooks (or type `/hooks`). See [Hooks](reference/hooks.md#what-the-hook-scripts-need). |
| Push notifications do not arrive | A kind is switched off in Settings > Notifications. Or no device is subscribed ("no device is subscribed to Web Push"). Or ntfy is down ("ntfy does not answer at ..."). Or the phone's Tailscale is off, because the ntfy server is tailnet-only. | Settings > Doctor > Notifications has a **Send test** button and the fix per row: open the board on the phone and enable notifications, or start ntfy (`sudo systemctl start ntfy`). The iPhone ntfy app must reach ntfy.sh for the wake-up. Without a public URL a notice has no link or buttons (Doctor, "Notification links"). See [Notifications](guide/notifications.md). |
| Settings > Doctor shows failing rows | Each failing row names its own cause. | Read the row's detail line and its fix: a sentence, a command with a **Copy** button, or a button that starts the fix. Press **Re-check** after fixing (it skips the 20 second cache). A row that says "did not answer in N s (the box is busy; this is not a failure)" is not a failure; check again later. See [Doctor and agents reference](reference/doctor.md). |
| The installer stops: "tailscale serve port 443 is already used by something else" | Another service already uses that HTTPS port on your tailnet name (another serve handler, a TCP forward or a Funnel). | Run `tailscale serve status` to see what holds it. Pick other ports, for example `CCBOARD_HTTPS_PORT=8443 CODE_HTTPS_PORT=10000 ./install.sh`. `CCBOARD_REPLACE_SERVE=1` replaces everything on that port: use it only when the port is yours. Port 443 is never taken from another service otherwise. See [Tailscale](install/tailscale.md#ports). |
| The installer stops: "port 8000 is in use and ccboard.service is not running" (or another port) | Something else listens on a loopback port ccboard wants. | The installer prints the process (`ss -ltnp`). Stop it, or choose another port, for example `CODE_SERVER_PORT=8081 ./install.sh`. |
| The installer stops: "HTTPS certificates are not enabled for this tailnet", "this node has no MagicDNS name" or "tailscale status failed" | The two admin-console switches are off, or Tailscale is not running or signed in. | Turn on **MagicDNS** and **HTTPS Certificates** on the DNS page of the Tailscale admin console, start and sign in to Tailscale, and rerun. |
| The installer stops: "run interactively" or "Ubuntu 22.04 or 24.04 required" | `sudo` needs a terminal (a remote session without one), or the distribution is not a supported Ubuntu. | On a remote machine: `ssh -t <host> 'cd ccboard && ./install.sh'`. Other distributions are not supported by the Linux installer. |
| Settings > Doctor says the tmux socket is missing, wrong, or the server runs on another socket | The board and the tmux server must agree on one socket, `/tmp/tmux-<uid>/ccboard` on Linux (the units pin `TMUX_TMPDIR=/tmp`) and `/private/tmp/tmux-<uid>/ccboard` on a Mac. A server started by hand, or with another `TMUX_TMPDIR`, uses a different one. | Ask the board's own server: `tmux -L ccboard display-message -p '#{socket_path}'`. The directory must be mode 0700 and the path at most 100 bytes. A hook from a tmux server on another socket is not trusted by pane id. Never restart `ccboard-tmux` while sessions run. The full notes are under [Details](#details). |
| The board says Claude is not logged in, or Home shows "Claude's login ... is not valid any more" | The login stood unused for a long time, or you logged out. Headless runs are deferred meanwhile. | Settings > Accounts, **Log in again** on the account's row (Codex has the same). The board never reads credential files; it learns of a dead login from a failure. See [Login expiry and re-login](guide/accounts.md#login-expiry-and-re-login). |
| The login link never appears, or the pasted code is refused | The login needs the whole `code#state` string, and codes expire quickly. | Open `/tty/?arg=_ccboard-login` and finish the login in the terminal. |
| On WSL2 the board disappears a few minutes after you close every terminal | WSL2 stops its machine when the last terminal closes, and that ends tmux and every session. | Register the keep-alive task from Windows PowerShell ([Install on Windows with WSL2](install/windows-wsl2.md)); Doctor's `wsl-keepalive` row checks it. |
| In container mode the board does not answer | The container is stopped or unhealthy. | `docker compose -f ~/.local/share/ccboard/compose/docker-compose.yml --profile prod ps`, then `docker logs --tail 50 ccboard`. A watchdog line in your crontab restarts a container that stays down. To go back to the systemd board: [Rollback](install/docker.md#rollback). |
| A Codex session waits at a prompt asking whether to update Codex, or whether to trust a folder | Codex asks at launch. The board never answers either prompt and never types into a pane that shows one, so the row shows as needing you. | Open the terminal and pick Skip. Never accept Codex's own update prompt (its default answer runs `npm install -g` and can break the install); update by hand: [Updating Codex on the box](guide/codex.md#updating-codex-on-the-box). Claude Code: [Updating Claude Code](upgrade.md#updating-claude-code). |

### Where the logs are

| System | Command |
|---|---|
| Linux (systemd) | `journalctl -u ccboard -u ccboard-ttyd -u ccboard-tmux -f` |
| Mac | `tail -n 30 ~/Library/Logs/ccboard/board.log` (also `tmux.log`, `ttyd.log`) |
| Container | `docker logs -f ccboard` (the startup line shows the runtime and image version); Watchtower's is `docker logs ccboard-watchtower` |
| Backup | `journalctl -u ccboard-backup` on Linux, `~/Library/Logs/ccboard/backup.log` on a Mac |

### Details

- *403 from localhost*: enable local sign-in and run `bin/ccboard-open`, or use the tailnet HTTPS address that supplies your identity. `curl http://127.0.0.1:8000/healthz` is the on-box health check.
- *"ccboard-tmux is not running"* banner: `sudo systemctl start ccboard-tmux`. Never `PrivateTmp`/`ProtectHome` these units; the tmux socket is `/tmp/tmux-<uid>/ccboard`.
- *Login link never appears*: open `/tty/?arg=_ccboard-login` and finish the login in the terminal. The pasted value must be the whole `code#state` string; codes expire quickly.
- *Ubuntu 22.04*: tmux 3.2a lacks `allow-passthrough` (Shift+Enter / notifications inside the TUI degrade); `tmux.conf` uses `-q` so it still loads.
- Logs: `journalctl -u ccboard -u ccboard-ttyd -u ccboard-tmux -f`; in docker mode the board's log is `docker logs -f ccboard` (the startup line shows the runtime and image version) and Watchtower's is `docker logs ccboard-watchtower`.
- *A busy box*: the board keeps its own load down. A hidden tab polls every 15 s instead of 3 s and polls at once when it is shown again. While the 1-minute load average is above the CPU count, the project scan reuses each repo's branch and dirty flag for up to 10 s (Home says "scan slowed (box is busy)" above the project list), and the cost refresh and the transcript indexer skip their pass and catch up once the box is quiet (at most an hour later). Sessions, hooks, permission answers and anything you start are never slowed. `/api/state` is gzipped for a browser (about 11 KB to 3 KB on the box). The static scripts, styles and pages under `/static` are gzipped too (about 1.6 MB of text to about 0.4 MB; `app/staticgz.py`): only for a client that sends `Accept-Encoding: gzip`, with `Vary: Accept-Encoding` and a separate ETag per variant, made once per file and kept in memory. Nothing that streams (the live tail, the MCP endpoint, the terminal) goes through it, and fonts and images are left as they are.
- *Where the tmux socket is*: ask the board's own server, a read-only command that is safe to copy: `tmux -L ccboard display-message -p '#{socket_path}'` (empty or an error means no server is running). On Linux with the shipped units it is `/tmp/tmux-<uid>/ccboard` (the units pin `TMUX_TMPDIR=/tmp`). In docker mode the container mounts that same directory from the host, so the path and the uid are the host's. On a Mac tmux does not use `$TMPDIR`, so it is `/private/tmp/tmux-<uid>/ccboard` (`/tmp` is a link to `/private/tmp`; the board compares real paths). The directory must be private to its owner (mode 0700) and the path at most 100 bytes (the limit itself is 103 bytes on macOS: a 104-byte path fails with "File name too long", measured 2026-10-10 on an Intel Mac, macOS 14; the board keeps a margin); Settings, Doctor, `tmux socket` shows both. A hook from a tmux server on any other socket is not trusted by pane id and falls back to matching the repository folder. If the doctor says the server is running but its socket file is gone, the tmux manual says the server recreates the socket when it gets `SIGUSR1`; the board never sends it, you run `kill -USR1 <pid>` yourself, and you never restart `ccboard-tmux` while sessions run. Measured on a Mac (tmux 3.6b, measured 2026-10-10 on an Intel Mac, macOS 14): a deleted socket came back after `kill -USR1` with the sessions intact; to verify on Linux. The doctor finds the server by its process title on a Mac and by its command line on Linux (`tmux -L <name> ...` or `-S <path>` with a command that starts a server, as the service's `-D` form does); on Linux the socket path comes from the doctor's own uid and `TMUX_TMPDIR`, so a service that runs with another `TMUX_TMPDIR` can make a "socket file gone" warning that is not true.
- *Docker mode, board not answering*: `docker compose -f ~/.local/share/ccboard/compose/docker-compose.yml --profile prod ps`, then `docker logs --tail 50 ccboard`; roll back as described in [Run the board as a container](install/docker.md#run-the-board-as-a-container-optional).

## FAQ

Each answer below comes from the code or from another page of these docs; the page is linked where there is one. Where something has not been tested, the answer says so.

### Do I need Tailscale?

Yes. The board binds only to the machine's own loopback address, and the only way in is `tailscale serve`, which adds the `Tailscale-User-Login` header that the board uses to know who you are. The installer stops with "tailscale is not installed" without it. Two things are optional: on WSL2 Tailscale may run on Windows instead of in the distro (`CCBOARD_TAILSCALE_PLACEMENT=host`), and the local sign-in is a second way into the board from the machine itself, not a way to do without Tailscale. Only the demo board you start for development runs without it ([Developing ccboard](development.md#demo-mode)). See [Tailscale](install/tailscale.md).

### Can I use it from the machine it runs on?

Not through plain `http://localhost`, which carries no Tailscale identity and gets a 403. You have two ways. The tailnet https name (`https://<name>.<tailnet>.ts.net`) should carry the identity even when you open it from the same machine; the one measurement of that was with curl on a Mac, and a real browser was not tried ([Tailscale](install/tailscale.md#tailscale-on-each-system)). Or switch on the optional local sign-in (`CCBOARD_LOCAL_SIGNIN=1`, off by default) and run `bin/ccboard-open`, which opens a one-minute link that signs you in as the first login in `CCBOARD_ALLOWED_USERS`; it is meant for a single-user machine ([Security](security.md#security-model)).

### Does it need an API key?

ccboard itself needs none, and neither does the install. The board starts the real `claude` or `codex` program, and those use the login you make once from the board (the Log in button): everything the board launches uses that same login. Do not put `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN` or `CLAUDE_CODE_OAUTH_TOKEN` in `/etc/ccboard/env` or in the tmux server's environment, because they take precedence over the interactive login. GitHub features use the `gh` login on the machine, not a key you give the board. See [Running on a subscription](guide/accounts.md#running-on-a-subscription-no-api-key).

### Is it multi-user?

No. It is one board per person: one Unix user and one list of allowed Tailscale logins. Everyone on that list gets the same board, and anyone your tailnet rules let reach the terminal port gets a shell as your user, so keep the list and your tailnet access short ([Security](security.md#who-can-reach-what)). Teammates appear only as presence read from GitHub ([Team](team.md)), and several boards can be paired as nodes ([Several devices](nodes/overview.md)), each with its own owner.

### What leaves my machine?

- **The agents' own traffic.** Claude Code and Codex talk to their vendors exactly as they do outside the board. The board adds nothing to that.
- **GitHub, through `gh` and git, as you.** Pull requests, CI status, issues and clones. Writes to GitHub that the board makes on its own (epics, a team presence comment) are off until you switch them on. The nightly backup also pushes your unpushed work to branches named `ccboard-backup/<node>/<branch>` on each repository's `origin`; `CCBOARD_BACKUP_PUSH=0` stops that ([Backup and restore](backup-and-restore.md)).
- **Backups.** The restic repository is on the same machine by default; it goes elsewhere only if you set `CCBOARD_RESTIC_REPO` to a remote. It holds your transcripts, encrypted with the password file.
- **Notifications.** The ntfy server runs on your machine. To wake an iPhone it relays a message with no content through ntfy.sh. Web Push goes through the browser's push service, and the board accepts subscriptions only for known browser push services.
- **Tailscale** carries the traffic between your devices and the machine, as it does for anything on your tailnet.
- **At install time**, downloads from apt, GitHub (the ttyd binary and the claude-mem plugin), code-server's installer, Claude's installer, ntfy's apt repository and npm (`ccusage`).
- **Nothing else that the code shows.** As far as a search of the app's code for outgoing addresses goes, it names no analytics or telemetry service, and the code-server settings the installer writes turn its telemetry and update checks off.

### Does it work offline?

Not tested, so no promise. What the code and these docs say each part needs: the board's own pages and the terminal run on your machine and reach your devices over Tailscale; Claude Code and Codex need their vendors; the GitHub features need GitHub; an iPhone push needs ntfy.sh for the wake-up; installing and updating need the network. The Doctor's version checks make no network call. Whether a tailnet that has lost its connection to Tailscale's servers keeps serving the board is a Tailscale question this repository does not answer.
