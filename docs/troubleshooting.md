# Troubleshooting and FAQ

For anyone whose board is not behaving.

[Back to the documentation index](README.md)

## Troubleshooting

- *403 from localhost*: enable local sign-in and run `bin/ccboard-open`, or use the tailnet HTTPS address that supplies your identity. `curl http://127.0.0.1:8000/healthz` is the on-box health check.
- *"ccboard-tmux is not running"* banner: `sudo systemctl start ccboard-tmux`. Never `PrivateTmp`/`ProtectHome` these units; the tmux socket is `/tmp/tmux-<uid>/ccboard`.
- *Login link never appears*: open `/tty/?arg=_ccboard-login` and finish the login in the terminal. The pasted value must be the whole `code#state` string; codes expire quickly.
- *Ubuntu 22.04*: tmux 3.2a lacks `allow-passthrough` (Shift+Enter / notifications inside the TUI degrade); `tmux.conf` uses `-q` so it still loads.
- Logs: `journalctl -u ccboard -u ccboard-ttyd -u ccboard-tmux -f`; in docker mode the board's log is `docker logs -f ccboard` (the startup line shows the runtime and image version) and Watchtower's is `docker logs ccboard-watchtower`.
- *A busy box*: the board keeps its own load down. A hidden tab polls every 15 s instead of 3 s and polls at once when it is shown again. While the 1-minute load average is above the CPU count, the project scan reuses each repo's branch and dirty flag for up to 10 s (Home says "scan slowed (box is busy)" above the project list), and the cost refresh and the transcript indexer skip their pass and catch up once the box is quiet (at most an hour later). Sessions, hooks, permission answers and anything you start are never slowed. `/api/state` is gzipped for a browser (about 11 KB to 3 KB on the box). The static scripts, styles and pages under `/static` are gzipped too (about 1.6 MB of text to about 0.4 MB; `app/staticgz.py`): only for a client that sends `Accept-Encoding: gzip`, with `Vary: Accept-Encoding` and a separate ETag per variant, made once per file and kept in memory. Nothing that streams (the live tail, the MCP endpoint, the terminal) goes through it, and fonts and images are left as they are.
- *Where the tmux socket is*: ask the board's own server, a read-only command that is safe to copy: `tmux -L ccboard display-message -p '#{socket_path}'` (empty or an error means no server is running). On Linux with the shipped units it is `/tmp/tmux-<uid>/ccboard` (the units pin `TMUX_TMPDIR=/tmp`). In docker mode the container mounts that same directory from the host, so the path and the uid are the host's. On a Mac tmux does not use `$TMPDIR`, so it is `/private/tmp/tmux-<uid>/ccboard` (`/tmp` is a link to `/private/tmp`; the board compares real paths). The directory must be private to its owner (mode 0700) and the path at most 100 bytes (the limit itself is 103 bytes on macOS: a 104-byte path fails with "File name too long", measured 2026-10-10 on an Intel Mac, macOS 14; the board keeps a margin); Settings, Doctor, `tmux socket` shows both. A hook from a tmux server on any other socket is not trusted by pane id and falls back to matching the repository folder. If the doctor says the server is running but its socket file is gone, the tmux manual says the server recreates the socket when it gets `SIGUSR1`; the board never sends it, you run `kill -USR1 <pid>` yourself, and you never restart `ccboard-tmux` while sessions run. Measured on a Mac (tmux 3.6b, measured 2026-10-10 on an Intel Mac, macOS 14): a deleted socket came back after `kill -USR1` with the sessions intact; to verify on Linux. The doctor finds the server by its process title on a Mac and by its command line on Linux (`tmux -L <name> ...` or `-S <path>` with a command that starts a server, as the service's `-D` form does); on Linux the socket path comes from the doctor's own uid and `TMUX_TMPDIR`, so a service that runs with another `TMUX_TMPDIR` can make a "socket file gone" warning that is not true.
- *Docker mode, board not answering*: `docker compose -f ~/.local/share/ccboard/compose/docker-compose.yml --profile prod ps`, then `docker logs --tail 50 ccboard`; roll back as described in [Run the board as a container](install/docker.md#run-the-board-as-a-container-optional).
